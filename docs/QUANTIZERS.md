## A. How it works, in one example

**Concept.** Every candidate does the same four steps on each block of values along a row of W
(the reduction axis of Y = W·X):

1. **Pick a shared scale** 2^e from the block's largest magnitude (class rule `ocp`: e = floor(log2 max) − emax_elem).
2. **Divide** every value in the block by 2^e.
3. **Round** each value to the element grid (round to nearest, ties to even), then **saturate** at vmax (no Inf/NaN).
4. **Multiply back** by 2^e. Only the 6-bit codes and the one shared exponent per block are stored.

What differs between the five formats is only the element grid in step 3 and how the block and exponent are organised.

**Data.** One block of six values, w = [6.0, 3.3, −1.06, 0.3, 0.07, 0]. Its max is 6.0, so floor(log2 6) = 2.

| format | stored exponent | result | what happened |
|---|---|---|---|
| MXFP6 E2M3 (emax 2) | e = 2 − 2 = 0, scale 1 | [6.0, 3.25, −1.0, 0.25, 0.125, 0] | 3.3 lies in binade [2,4), step 0.25 → 3.25. 0.3 and 0.07 are below 2^emin = 1: **subnormals**, fixed step 0.125, so they survive |
| MXINT6 | E = 2, step 2^(2−4) = 0.25 | [6.0, 3.25, −1.0, 0.25, **0**, 0] | one fixed step for the whole block; 0.07 is 0.28 steps → **zeroed** |
| BFP6 16\|4\|5 | E = 2 (4-bit field), step 0.25 | same as MXINT6 here | same grid as MXINT6; differs only through block size 16 and the 4-bit exponent |
| MXFP6 E3M2 (emax 4) | e = −2 | [6.0, 3.5, −1.0, 0.3125, 0.0625, 0] | more range, but only 2 mantissa bits: 3.3 → 3.5 |
| MXFP6 E4M1 (emax 8) | e = −6 | [6.0, 3.0, −1.0, 0.25, 0.0625, 0] | 1 mantissa bit: coarse everywhere |

**Two edge cases everyone should know.**
- *RNE tie:* E2M3 with scale 1, 1.0625 sits exactly between 1.0 and 1.125 → goes to the even code → 1.0.
- *The floor rule can clip the block max.* E2M3's vmax is 7.5 but the floor rule allows a scaled max up to just under 8. A block max of 7.9 → 7.5.
  The Lecture 19 notebook counts this two ways, and so do we: **range** (7.9 > 7.5 before rounding) and **saturated**
  (the rounded value, 8.0, is beyond 7.5). A value of 7.6 is "range" but not "saturated" (it rounds to 7.5 anyway).

**Observation on dataset C** (held-out Y error, class rule; `T1_main_C.md`): E2M3 3.10% < BFP6 3.48% < MXINT6 4.05% < E3M2 5.47% < E4M1 11.15%.
At 6 bits, for this mildly heavy-tailed matrix, mantissa precision (E2M3's 3 bits + subnormals) beats exponent range.

**One-sentence statements the report must contain.**
- BFP with 32 values, an 8-bit exponent, the floor rule and RNE is numerically identical to MXINT6 (unit test `test_v2_bfp_32_8_5_identical_to_mxint6`). Our BFP6 differs from MXINT6 only through block size (16) and exponent width (4 bits), which costs 6.28 instead of 6.32 bits/element.
- The 4-bit BFP exponent limits BFP6 to |w| ≤ 31·2^3 = 248 and to blocks whose max is at least 2^−8. W_C's block exponents lie in [−2, 2], so no block of C is clamped (`T6`, "clamped blocks" = 0).
- E4M1 conventions (`T3`): no reserved code (vmax 384) 11.15%, top exponent reserved (192) 11.15%, one NaN (256) 20.66% under the class rule. With `ceil`, all three give 10.24%. E4M1 loses to E2M3 under every convention.
- MXINT6 symmetric vs two's complement (`T8`): ≤ 0.01 pp apart under the class rule on all five datasets, but up to 0.06 pp under `opt`.

## C. Limitations
- `opt` searches only 4 exponents per block and uses the block's diagonal slice of XXᵀ when output-aware.
- W+X mode quantizes X with the same format and policy as W; mixed formats are out of scope (D4).
- BFP6's exponent range [−8, 7] is fine for C but would clamp a layer whose block maxima are below 2^−8.
